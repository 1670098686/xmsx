> **分层调用强制约束：**
>
> 1. UI 层（ui 目录）**不允许直接操作数据库、不调用 tool_layer/agent 底层函数**；UI 所有请求调用 `business` 业务层接口。耗时操作（导入、解析、备份、导出）必须用 `ui/widgets/worker.py` 的 QThread 子线程执行。
> 2. business 业务层可以调用 `agent` 智能体层、`tool_layer` 工具层、`data_layer` 数据层；business 负责会话编排、降级授权弹窗、落库与日志。业务通用函数（写操作日志、获取存储路径、异常转码）统一调用 `business/service_common.py`。
> 3. agent 智能体层可调用 `tool_layer` 工具层与 `config`，**不能访问数据库、不能导入 UI/business**；LangGraph 状态图拓扑固定（plan→act→observe→reflect⇄act→verify→(refine⇄act)→finish），节点间只通过 AgentState 传递数据。
> 4. tool_layer 工具层**不能访问数据库、不能导入 agent 层**，只负责文件、文本、视觉与 AI HTTP 通信；文件/表格/OCR 的解析实现留在 tool_layer，工具注册表与 function calling 多轮执行器统一收口在 `agent/tools.py`，禁止 LangGraph 节点里直接写文件解析逻辑。
> 5. data_layer 只做 CRUD，不包含业务判断逻辑。
> 6. 禁止逆向调用：数据层不能导入业务层，工具层不能导入 UI/agent 层，agent 层不能导入 business/UI 层。

## 二、Python 编码规范

1. 整体遵循 **PEP8 规范**，使用 4 空格缩进，不用 tab；行宽最大 120 字符。
2. 命名：
   - 文件夹、py 文件：`snake_case` 小写下划线，如 `literature_import.py`
   - 类名：大驼峰 `MainWindow、LitImportService`
   - 变量、函数：小写下划线 `literature_id、get_literature_list()`
   - 常量：全大写 `SUPPORT_SUFFIX = {".pdf", ".txt", ".docx", ".doc"}`
3. 每个函数、类必须写文档字符串 `""" """`，写明入参、返回值、异常。

```python
def import_literature(file_path: str) -> tuple[int, str]:
    """导入单篇文献

    Args:
        file_path: 本地文件绝对路径
    Returns:
        tuple: (code, msg) code 0 成功，非 0 代表错误码；msg 提示信息
    """
```

4. 禁止写魔鬼数字，所有状态、尺寸、颜色统一放到 `config` 下常量，不在业务代码硬编码颜色值、窗口宽高。Agent 进度锚点、多轮循环上限等集中在 `config/constants.py`，禁止散落在代码各处。
5. 导入顺序：标准库 → 第三方库（PyQt5 / pdfplumber / jieba / PyMuPDF）→ 项目内部模块；分组空行隔开。
6. 禁止 `from xxx import *`，明确导入类/函数。
7. 测试技巧：`agent.tools.split_text_chunks` 的 `size/overlap` 是函数默认参数（定义时绑定常量），monkeypatch `C.AI_INLINE_CHUNK_CHARS` 不生效；测试切小块需 monkeypatch `agent.tools` 模块函数本身包一层传 size。

## 三、数据库开发规则（SQLite）

1. 数据库共 **7 张表** + 1 张中间表 + 1 张备份记录：`literature_info`（文献元数据）、`literature_report`（解析报告）、`literature_note`（批注）、`category_tag`（标签）、`literature_tag`（文献-标签中间表）、`parse_rule`（解析规则）、`system_config`（系统配置 + AI 模型加密存储）、`operation_log`（操作日志）、`backup_record`（备份记录）。严格按照概要设计文档字段设计，不随意新增/修改字段。
2. 数据库连接使用**单例模式**，由 `data_layer/db_connect.py` 统一管理，全局共用一个 sqlite 连接，禁止频繁重复打开关闭数据库。
3. 所有 SQL 禁止字符串拼接，全部使用参数化查询，防止注入。

```python
# ✅ 正确
cur.execute("select * from literature_info where id=?", (lit_id,))
# ❌ 禁止
cur.execute(f"select * from literature_info where id={lit_id}")
```

4. 业务发生重要操作（导入、解析、删除、备份），必须写入 `operation_log` 操作日志表（通过 `business/service_common.py` 的 `write_operation_log` 统一入口）。高危操作（删除文献、清空笔记）捕获异常后记录操作日志时，操作状态标记为 0（失败）。
5. 数据表初始化：程序启动检测表是否存在，不存在自动执行建表脚本（`data_layer/db_init.py`）；版本迭代考虑简单数据库迁移（schema version 字段）。
6. 禁止在 dao 层写复杂业务逻辑，复杂查询组装放到 business 层。

## 四、UI (PyQt5) 开发强制规则（对齐 UI 规划文档）

1. UI 层职责：只负责渲染界面、捕获按钮/输入事件，**业务逻辑全部移交 business 层**。UI 拿到业务返回结果再刷新界面、弹窗提示。
2. 样式统一：**不要硬编码写颜色、字体、字号**，全部读取 `config/global_config.py` 中定义的主题变量；浅色/深色主题切换全部走 `theme_manager.py`，每个控件样式跟随主题；主题样式表放在 `resources/qss/`。
3. 窗口布局：
   - 左侧导航栏宽度固定 `220px`，顶部导航高度固定 `40px`；只有右侧内容区域自适应缩放。
   - 所有弹窗、二次确认高危操作弹窗统一封装在 `ui/widgets/dialogs.py`，删除、覆盖、批量清除必须二次确认。
4. 交互规范：
   - 耗时操作（导入、解析、备份、导出）**禁止 UI 线程直接执行**，必须使用 `ui/widgets/worker.py` 的 QThread 子线程处理，UI 展示 `ui/widgets/loading.py` 进度条，避免界面卡死。
   - 成功/失败提示统一调用全局轻量 `ui/widgets/toast.py`，不要重复写 QMessageBox。
   - 控件 hover 状态、禁用状态统一使用全局样式，禁止每个页面单独写样式。
   - PDF 批注选框在用户完成批注编辑并保存前应保持显示（蓝色虚线框 + 「新」角标），支持 Esc 或翻页取消。
   - 从其他应用切换回窗口时，第一下点击仅激活窗口，不会触发控件操作，确保管理中心子页面状态保持。
5. 页面切换：右侧页面采用堆栈 QStackedWidget 内嵌切换，不做新窗口弹出，保证沉浸式双栏布局。
6. 空状态处理：检索为空、无导入文献等场景必须展示 `ui/widgets/empty_state.py`（空提示 + 引导按钮），不能空白。
7. 文件查看一致性：上传的文件查看原文时应以上传的格式进行展示，PDF 文献显示可批注的功能页面。

## 五、异常处理规则

1. 自定义业务异常，在 `utils/exceptions.py` 定义：`AIServiceError、FileInvalidError、ParseError、StorageNotEnoughError` 等。
2. 分层异常捕获：
   - tool_layer 捕获底层 IO、文件读取、PDF 解析异常，包装成自定义业务异常向上抛出。
   - agent 层捕获 function calling 多轮循环中的工具失败（回灌错误让 AI 改道）、模型整体失败（原子通读降级）。
   - business 层捕获业务异常，生成错误信息，调用 `service_common.exception_to_code` 统一转码，记录日志。
   - UI 层捕获业务返回错误码/异常，展示 toast 弹窗给用户，**绝对不能直接把原始堆栈抛给用户界面**。AI 模型传回的错误信息要以弹窗形式告诉用户发生了什么错误。
3. 所有耗时操作必须增加 try except 兜底，软件不能因为单篇文献解析失败直接闪退；捕获异常写入日志文件（`utils/logger.py`）。
4. 高危操作捕获异常后记录 operation_log（操作状态标记 0 失败）。
5. 禁止空 except：不要写 `except: pass`，至少捕获明确异常类型，打印日志。

```python
# ❌ 不允许
try:
    do_something()
except:
    pass
```

6. 致命失败判定：三重校验器对 `abs_text` 为空判致命，business 层必须同时检查 `state.error` 与 `verify_result.fatal`，防止落库"成功的空报告"。

## 六、接口调用 & 模块联调约定

1. 业务层向外提供接口全部使用返回码模式：统一返回 `(code: int, data: any, msg: str)`，code=0 表示成功，code>0 表示业务错误码。
2. 解析业务 `literature_parse.py.parse_single` 实际返回五元组：`(report, keywords, engine, warnings, ai_error)`，其中 `engine` 取值仅为 `agent_ai`（Agent 正常收尾，含 AI 不可用转本地）、`agent_local`（Agent 自身异常的纯本地兜底）、`local`（Legacy 下线后的纯本地链）。
3. UI 不直接调用 dao，全部调用 business 暴露的 service 函数。
4. 全局状态：当前选中文献 id、当前主题模式，统一放在 `config` 全局对象，禁止各个页面自己单独存副本。
5. 模块之间尽量传 id（文献 id、标签 id），不要传递大对象实例；数据全部从数据库读取，减少内存缓存。
6. 解析报告存储：解析完成后报告一律存入配置的解析报告存储目录（`report_path`），不再存入文献原件目录；"另存为"才让用户自选目录。
7. 旧版 `.doc` 格式：通过本地 Word/WPS/LibreOffice 转为 `.docx` 后导入，转换产物使用系统临时目录并在提取后立即删除。

5. 解析维度动态控制：规则模板中解析维度取消勾选后，文献解析的结构化报告对应维度不显示，输出也不包含该维度。

7. 更改解析规则时，无需对已经解析的文献重新进行解析。

## 十二、AI 主导文献解析（LangGraph 智能体）强制规则

### 1. 原件优先、零预处理

有可用模型与原件通道时，版式体检（`inspect_document`）之后**第一步即把文献原件**（file_id 托管 / PDF Base64 内联）**直传模型通读**，禁止先做本地文本提取、章节切分等预处理；无模型/网络失败才走纯本地链。

### 2. 读中自主调工具（function calling 内部循环）

AI 通读原件期间，通过标准 `tools` / `tool_calls` 协议自主决定调用中间件工具：
- `extract_tables`：PDF 表格取证（pdfplumber `page.find_tables().extract()`）、docx 表格（python-docx `document.tables`），统一 GitHub 风格 Markdown；
- `ocr_page`：图表页/扫描页识别（AI 视觉 `chat_with_vision`，失败降级本地 Tesseract，两轨皆不可用跳页）；
- `detect_structure`：章节取证（含 `precision` 参数）；
- `extract_text`：补全文本层。

工具由 `agent/tools.py` 的多轮执行器在**本地执行**，结果以 `role=tool` 消息回灌对话上下文，再由 AI 继续通读，直到 AI 自行输出最终六维度 JSON。

### 3. 多轮循环安全边界（常量统一在 `config/constants.py`）

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `AGENT_TOOL_MAX_ROUNDS` | 5 | FC 多轮循环轮数硬上限 |
| `AGENT_TOOL_MAX_CALLS` | 8 | 单轮内最大工具调用次数 |
| `AGENT_TOOL_RESULT_MAX_CHARS` | 6000 | 工具结果长度截断上限 |
| `AGENT_TOOL_RESULT_TAIL_CHARS` | 1000 | 截断后尾部保留字符数 |

- 同一（工具名 + 参数 JSON）**签名去重**：重复调用直接返回 ok=True 提示文本不执行；
- 页码必须做越界校验（`agent/llm.py.sanitize_tool_call`），page_index 不在 [0, page_count) 范围内拒绝；
- 达到上限强制关闭 tools 并追加提示让模型收尾，不得死循环；
- 每个工具结果做长度截断/摘要，防止多轮上下文超模型上限。

### 4. 两种网关适配

- **Plan A（默认）**：原件消息 + tools schema 同框发送，AI 自主决定是否调用工具；
- **Plan B（降级）**：网关拒绝同框（`is_tools_unsupported` 判定协议类报错）时，先纯文本 FC 依据体检报告完成取证调度，再把取证结果注入 prompt 做一次性原件通读。

降级判定只认协议特征（`ai_client.is_tools_unsupported` 统一判定 tools 协议词 + 4xx 提示双命中），网络/鉴权类错误不得静默降级；实际采用的模式写入 `final_report.ai_channel` 留痕（`agent_ai_file` / `agent_ai` / 空串）。

### 5. 本地参与最小化但保留信任锚点

- `extract_keywords` **始终本地 jieba** 执行并以其结果入库，AI 返回的 keywords 仅作参考，防止幻造关键词；
- `detect_structure` 改为**条件触发**：仅当 AI 草稿 `reference_list` 为空时才由本地规则兜底切分；AI 已给出参考文献时不重复跑；
- 扫描件经原件通道成功但本地无文本层时，仍须保证逐页 OCR 基线可供校验，基线缺失判致命、不落空报告；
- **FC 副产物回流**：工具执行结果经 `fc_byproducts`（text/ocr_pages/tables/structure）带出，`observe_node._merge_fc_byproducts` 写回 state 作为三重校验基线。

### 6. 进度锚点（常量统一在 `config/constants.py`，任何分支百分比只许前进不许倒退）

```
├── 0-8     Plan 准备解析任务
├── 8-10    inspect_document 版式体检
├── 12-70   ai_read_original 原件通读 + 读中 FC 多轮循环
│           （按轮次均分打标，单调前进）
├── 71      条件尾部：extract_text（无全文时）/ ocr_page（扫描件补缺页）
├── 72-74   extract_keywords 本地 jieba
├── 76      verify（原件信任旁路：非本地权威维度齐全，只查完整性）
├── 77      verify（首次完整三重校验：完整性 / 一致性 / 原文溯源）
├── 80-84   阶段5：单步兜底 Director（缺失维度 ai_deep_analyze）
├── 85-89   Refine 补救（封顶 89，不超过 finish）
└── 90      finish 智能体流程结束，等待业务层落库
```

### 7. 校验与补救

原件成功且非本地权威维度齐全可走**信任旁路**（`ai_original_trusted`），只查完整性；否则跑完整性/一致性/原文溯源三重校验。溯源校验采用**双向覆盖率**：AI 侧 ≥ 0.35 且共同词 ≥ 3 或本地侧 ≥ 0.15，任一通过即可。补救（Refine）按 `(维度, 问题类型)` 计数并设上限 `AGENT_REFINE_MAX_ATTEMPTS=2`，超限带告警收尾。

### 8. AI 失败兜底与授权

function calling 多轮循环中任何单轮/单工具失败都不得闪退：
- 工具失败把错误文本回灌让 AI 改道；
- 模型整体失败回退一次性原子通读；
- 再失败按通道降级规则处理（`is_file_channel_degradable`：协议拒绝/超限可降级全文文本，网络/鉴权不降级）；
- **原件→全文文本的降级必须弹窗获得用户授权**（`literature_parse.py.degradation_callback`，UI 路径注入）；
- Agent 整体异常才用纯本地规则兜底（`engine=local`，msg 带"本地规则兜底"）。

### 9. 提示词与 schema 收口

- 系统/用户提示词全部外置在 `resources/prompts/`（`ai_system_prompt.txt`、`ai_parse_user_prompt.txt`、`ai_precision_guides.json` 等），由 `agent/prompts.py` 加载；
- function calling 工具的 JSON Schema 与可暴露工具白名单统一定义（`agent/tools.py.FC_TOOL_SCHEMAS`），**禁止向模型暴露 inspect/收尾类内部工具**；
- 要求模型六维度值输出**完整语句段落**、引用用**中文引号**、只输出约定 JSON 协议；
- 传输标记防泄漏：`agent/tools.split_citation_marks` 统一剥除模型照抄的 `【段落 n】/【片段 i/N】` 标记。

### 10. 留痕与本地化

`final_report` 记录：
- `parse_engine`：`agent_ai` / `agent_local` / `local`
- `ai_channel`：`agent_ai_file`（file_id）/ `agent_ai`（file_data / 文本）/ 空串（纯本地）
- `ai_read_original`：原件直读耗时、轮次数
- `fc_trace`：function calling 实际工具调用序列（含失败计数）
- `ai_error`：首个致命 AI 错误原文随报告回传（UI 弹窗展示）

遵守第九章，文献数据全程不出本机、模型密钥本地加密存储。
