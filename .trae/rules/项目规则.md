## 一、项目目录结构强制规范

严格遵循**四层架构（界面展示层、业务逻辑层、工具解析层、数据持久层）** 进行代码分包，禁止跨层直接调用。
literature_agent/

├── config/                     # 全局配置模块

> 分层调用强制约束：

1. UI 层（ui 目录）**不允许直接操作数据库、不调用 tool_layer 底层解析函数**；UI 所有请求调用`business`业务层接口。
2. business 业务层可以调用`tool_layer`工具层、`data_layer`数据层。
3. tool_layer 工具层**不能访问数据库**，只负责文件、文本处理。
4. data_layer 只做 CRUD，不包含业务判断逻辑。
5. 禁止逆向调用：数据层不能导入业务层，工具层不能导入 UI 层。

## 二、Python 编码规范

1. 整体遵循 **PEP8 规范**，使用 4 空格缩进，不用 tab；行宽最大 120 字符。
2. 命名：
   - 文件夹、py 文件：`snake_case`小写下划线，如`literature_import.py`
   - 类名：大驼峰`MainWindow、LitImportService`
   - 变量、函数：小写下划线`literature_id、get_literature_list()`
   - 常量：全大写`SUPPORT_SUFFIX = {".pdf",".txt",".docx",".doc"}`
3. 每个函数、类必须写文档字符串`""" """`，写明入参、返回值、异常。
def import_literature(file_path: str) -> tuple[int, str]:
    """导入单篇文献
    Args:
        file_path: 本地文件绝对路径
    Returns:
        tuple: (code, msg) code 0成功，非0代表错误码；msg提示信息
    """
4. 禁止写魔鬼数字，所有状态、尺寸、颜色统一放到`config`下常量，不在业务代码硬编码颜色值、窗口宽高。
5. 导入顺序：标准库 → 第三方库 (PyQt5/pdfplumber/jieba) → 项目内部模块；分组空行隔开。
6. 禁止`from xxx import *`，明确导入类 / 函数。

## 三、数据库开发规则（SQLite）

1. 数据库共 7 张表，严格按照概要设计文档字段设计，不随意新增 / 修改字段。
2. 数据库连接使用**单例模式**，全局共用一个 sqlite 连接，禁止频繁重复打开关闭数据库。
3. 所有 sql 禁止字符串拼接，全部使用参数化查询，防止注入。
# ✅正确
cur.execute("select * from literature_info where id=?", (lit_id,))
# ❌禁止
cur.execute(f"select * from literature_info where id={lit_id}")
1. 业务发生重要操作（导入、解析、删除、备份），必须写入`operation_log`操作日志表。
2. 数据表初始化：程序启动检测表是否存在，不存在自动执行建表脚本；版本迭代考虑简单数据库迁移。
3. 禁止在 dao 层写复杂业务逻辑，复杂查询组装放到 business 层。

## 四、UI (PyQt5) 开发强制规则（对齐 UI 规划文档）

1. UI 层职责：只负责渲染界面、捕获按钮 / 输入事件，**业务逻辑全部移交 business 层**。UI 拿到业务返回结果再刷新界面、弹窗提示。
2. 样式统一：**不要硬编码写颜色、字体、字号**，全部读取`config/global_config.py`中定义的主题变量；浅色 / 深色主题切换全部走`theme_manager.py`，每个控件样式跟随主题。
3. 窗口布局：
   - 左侧导航栏宽度固定`220px`，顶部导航高度固定`40px`；只有右侧内容区域自适应缩放。
   - 所有弹窗、二次确认高危操作弹窗统一封装在`ui/widgets/dialogs.py`，删除、覆盖、批量清除必须二次确认。
4. 交互规范：
   - 耗时操作（导入、解析、备份、导出）**禁止 UI 线程直接执行**，必须使用`QThread`子线程处理，UI 展示 loading 进度条，避免界面卡死。
   - 成功 / 失败提示统一调用全局轻量 toast 提示组件，不要重复写 QMessageBox。
   - 控件 hover 状态、禁用状态统一使用全局样式，禁止每个页面单独写样式。
5. 页面切换：右侧页面采用堆栈 QStackedWidget 内嵌切换，不做新窗口弹出，保证沉浸式双栏布局。
6. 空状态处理：检索为空、无导入文献等场景必须展示空提示 + 引导按钮，不能空白。

## 五、异常处理规则

1. 自定义业务异常，在`utils/exceptions.py`定义：`FileInvalidError、ParseError、StorageNotEnoughError`等。
2. 分层异常捕获：
   - tool_layer 捕获底层 IO、文件读取异常，包装成自定义业务异常向上抛出。
   - business 层捕获业务异常，生成错误信息，记录日志。
   - UI 层捕获业务返回错误码 / 异常，展示 toast 弹窗给用户，**绝对不能直接把原始堆栈抛给用户界面**。
3. 所有耗时操作必须增加 try except 兜底，软件不能因为单篇文献解析失败直接闪退；捕获异常写入日志文件。
4. 高危操作捕获异常后记录 operation_log（操作状态标记 0 失败）。
5. 禁止空 except：不要写`except:pass`，至少捕获明确异常类型，打印日志。
# ❌不允许
try:
    do_something()
except:
    pass
## 六、接口调用 & 模块联调约定

1. 业务层向外提供接口全部使用返回码模式：统一返回`(code:int, data:any, msg:str)`
   - code=0：成功；code>0 业务错误码。
2. UI 不直接调用 dao，全部调用 business 暴露的 service 函数。
3. 全局状态：当前选中文献 id、当前主题模式，统一放在 config 全局对象，禁止各个页面自己单独存副本。
4. 模块之间尽量传 id（文献 id、标签 id），不要传递大对象实例；数据全部从数据库读取，减少内存缓存。

## 七、单元测试要求

1. tests 目录编写单元测试，重点覆盖：
   - 文件校验、格式检测、去重逻辑
   - 数据库 CRUD
   - 文献解析文本提取
   - 导出、备份逻辑
2. 测试数据库使用临时内存 sqlite，不污染开发环境数据库。
3. 开发完成一个功能模块，同步编写对应测试用例。

## 八、开发优先级（对齐 UI 落地开发流程）

1. 阶段 1：基础框架
   - 数据库初始化、全局配置、主窗口双栏布局、主题切换、通用组件封装。
2. 阶段 2：四大核心业务
   - 文献导入 → 文献解析 → 文献检索 → 笔记批注（UI 页面 + business 业务 + dao 层 + 单元测试）
3. 阶段 3：管理中心模块
   - 标签管理、解析规则配置、存储路径、AI 模型配置、导出备份恢复。
4. 阶段 4：全流程联调、适配优化、bug 修复、低配设备轻量化优化。

## 九、安全 & 业务约束编码规则

1. 本系统**全程本地化，禁止任何网络上传用户文献、笔记数据**；AI 模型密钥本地加密存储 sqlite，不对外发送。
2. 文件路径操作，必须做路径安全校验，防止路径穿越漏洞。
3. 删除数据、清空笔记、覆盖备份等高危操作：业务层也要二次校验，不能仅靠 UI 弹窗。
4. 自动保存防抖：笔记模块防抖 1 秒，不要每次输入都频繁写数据库。

## 十、代码评审规则

1. 功能开发完成提交 merge，至少一位其他团队成员做代码评审。
2. 评审重点：分层是否越层调用、异常是否处理、sql 参数化、是否硬编码常量、UI 逻辑是否侵入业务层。
3. 禁止提交未注释的魔法数字、大段注释掉的废弃代码，废弃代码直接删除。
